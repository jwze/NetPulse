# NetPulse · 网络脉搏

纯前端的网络测速与质量监测面板。打开即可测速，不需要注册、不需要后端，所有数据只留在你自己的浏览器里。

## 特性

- **多线程并发测速**：1–64 线程可调，实时吞吐曲线
- **满载延迟评级（Bufferbloat）**：测速时并行探测，按增量分 A+ ~ F，衡量视频会议与游戏体验
- **成绩卡**：canvas 本地绘制分享图，导出 PNG 或复制到剪贴板，不含 IP
- **三种运行模式**：单节点、节点组联测、多节点按流量轮换
- **自定义节点**：增删改查、分组管理、连通性检测、JSON 配置导入导出
- **流量与带宽上限**：达到上限自动停止，避免跑飞
- **定时任务**：按间隔循环，或仅指定时段运行
- **后台保活**：切到后台继续跑（移动端适配 iOS）
- **出口信息**：当前出口 IP、归属地与国内 / 海外延迟
- **网络诊断**：ASN / 机房标记、IPv4-IPv6 双栈探测、DoH 多解析器对比、链路质量（延迟 / 抖动 / 丢包）、上行带宽测试
- **全球延迟**：40 个海外服务 + 按出口国家自动切换的本地常用包，真实 HTTPS 往返、冷启动、抖动与边缘节点
- **多出口识别**：同时问 51 个来源「我是谁」，按 ASN 合并同一网络，区分本机与代理出口，七项结论指出哪类站点走了另一条路
- **IP 质量**：12 个来源交叉验证归属、类型与风控标记，8 个邮件黑名单，100 分制评分
- **解锁检测**：148 个服务逐个看「它以为你在哪」，四类成绩单与分流建议
- **隐私画像**：87 项嗅探加 11 项伪装检测，一句话画像、A+ ~ F 环境评分，可一键隐藏全部地址
- **综合判定**：本地常用与海外服务分段比较，指出慢在国际出口、代理线路还是本机网络，并给出游戏 / 通话 / 流媒体 / AI / 开发的可用度
- **结果分享**：延迟结果可导出 PNG 分享图、生成不含 IP 的结果链接，并与本机上一次结果逐项对比
- **IPv6 测试**：六项检测（IPv6 / IPv4 / 双栈 / 大数据包 / 地址直连）打到 10 分制，识别 AAAA 过滤、PMTU 黑洞、NAT64 与隧道地址
- **IPv4 / IPv6 对比**：同一批网络两种协议同时测往返，看出 IPv6 是更快、一样还是绕路
- **网络拓扑**：WebRTC + STUN 探测内网地址、NAT 类型与双层 NAT
- **多节点对比**：并发打 2–3 个节点，比较线路差距
- **历史与导出**：测速结果存本机，最多 50 条，可导出 CSV / JSON
- **可离线**：Service Worker 预热全部构建产物，断网也能打开，可安装到桌面
- **息屏模式**：大字号时钟 + 实时速率
- 日间 / 夜间 / 跟随系统三档主题

## 测速节点

内置节点来自 `public/nodes.json`，字段说明：

| 字段 | 说明 |
| --- | --- |
| `link` | 测速资源地址 |
| `status` | 是否启用 |
| `webVisible` | 是否在网页端展示 |
| `method` | `GET` / `POST` / `HEAD` |
| `httpProtocol` | 通常保持 `AUTO` |
| `testMode` | 目前网页端主要使用 `DOWNLOAD` |

```json
{
  "list": {
    "全球[Global]": {
      "Cloudflare": {
        "link": "https://speed.cloudflare.com/__down?bytes=99614720",
        "status": true,
        "webVisible": true,
        "method": "GET",
        "httpProtocol": "AUTO",
        "testMode": "DOWNLOAD"
      }
    }
  }
}
```

修改后刷新页面生效。也可以在界面里的「自定义节点」中临时添加，节点会存进 `localStorage`，并支持导出为 JSON 迁移。

## 网络诊断

`/diagnostics` 页把浏览器能拿到的网络信息都摊开，全部走公开接口或本地 API：

| 卡片 | 数据来源 | 说明 |
| --- | --- | --- |
| 出口地址 | `ipwho.is` → 回退 `ipapi.co` | IP 版本、归属、ASN、时区、机房 / 代理 / VPN 标记 |
| 双栈探测 | `v4.ident.me` / `v6.ident.me` | 只监听对应协议栈，成功即代表该栈可用 |
| 本机环境 | Performance API、UA-CH、`navigator.connection` | 当前页面 HTTP 协议版本、网络类型、硬件信息，完全不出网 |
| DNS 解析对比 | `dns.alidns.com`、Cloudflare DoH、Google DoH | 同一域名的解析结果横向对比，差异可能来自 CDN 调度或 DNS 污染 |
| 链路质量 | 华为 / Cloudflare 204 端点 | 20 次小请求测延迟，据此算抖动与丢包 |
| 上传测速 | `speed.cloudflare.com/__up` | 4 路并发上传数据块，按完成量 / 耗时估算上行带宽 |
| 网络拓扑 | 小米 / 腾讯 / 哔哩哔哩 STUN | 解析 ICE 候选得出内网地址、NAT 类型与双层 NAT |
| 多节点对比 | 内置或自定义测速节点 | 并发拉流 8 秒，比较各路抢到的带宽 |

国内网络环境下 Cloudflare、Google 的 DoH 可能被拦截，界面会如实显示「无响应或被拦截」——这本身也是诊断结论。

## 全球延迟

`/latency` 页量的是「往返时延」而不是带宽：浏览器向每个服务自己的边缘节点发真实 HTTPS 请求，先发一次不计时的预热完成 DNS + TCP + TLS，之后的请求复用同一条连接，取中位数。

- **服务清单**：40 个海外服务，覆盖 AI、常用网站、影音、社交、开发、游戏与 CDN 骨干；另按出口国家自动选一组本地常用服务（中国大陆 / 中国台湾 / 日本 / 韩国 / 俄罗斯 / 印度 / 东南亚 / 欧洲 / 拉美 / 北美 / 中东），可手动切换
- **每个样本的记录**：冷启动耗时、中位数、相邻样本差的均值（抖动）、边缘节点代码（Cloudflare `colo`、`x-served-by`、`x-amz-cf-pop`）
- **出口识别**：并行询问 Cloudflare、ip.sb、ipwho.is、ipinfo.io、双栈专用主机与 STUN，按 ASN 合并同一网络，机房 IP 标记为代理；若某国通常不可直连的服务反而都有响应，会提示存在检查看不到的出口
- **判定**：本地常用与海外服务分别取中位数分档（≤80ms 好 / ≤150ms 一般 / 更慢偏慢 / 过半无响应为不通），组合出「两端可用」「远端偏慢」「海外比本地还快」「本机网络偏慢」「几乎全部不通」；再按游戏、视频通话、流媒体、AI、开发各自的阈值给出可用度
- **分享**：结果可以导出 1200×630 PNG，或复制一条把结果放在 `#lat=` 里的链接；链接只含时间、本地包、出口的国家 / 城市 / 网络与每个服务的中位数，不含 IP。打开链接会直接还原结果，并与本机上一次结果按 20ms / 30% 容差对比

计时 URL 都指向静态文件或 `generate_204` 这类边缘应答，避免把应用服务器的处理时间算进往返。

## IPv6 测试

`/ipv6` 页判断的不只是「有没有 IPv6」，还有它会不会拖慢上网。六项测试同时发出，用最先响应的站点作答，每项的站点分布在多个网络（Cloudflare / Google / DNSPod / 阿里 DNS / ipify / icanhazip），一家被墙不会让整项失败。

| 测试 | 在测什么 |
| --- | --- |
| 只有 IPv4 的网站 | IPv4 通不通，出去的地址是什么 |
| 只有 IPv6 的网站 | IPv6 通不通，DNS 有没有给出 AAAA |
| 双栈网站 | 浏览器选了哪个协议，要不要先等 IPv6 超时 |
| IPv6 大数据包 | 3.5 KB 的 URL 在新连接上发出，满尺寸数据包能否双向通过（PMTU 黑洞时小请求正常、大请求卡死） |
| IPv6 地址直连 | 不查 DNS 直接连 IPv6 地址 |
| IPv4 地址直连 | 直接连 IPv4 地址，用来认出只有 IPv6、靠 NAT64 打开 IPv4 网站的运营商 |

- **评分**：满分 10 分，IPv6 可用 4、大数据包 2、双栈不用等 2、不靠 DNS 1、浏览器优先 IPv6 1；IPv6 首次响应超过 3 秒扣 1
- **结论**：已支持 / 部分可用 / DNS 不给 AAAA / 没有 IPv6 / 只有 IPv6 / NAT64 / 全部无响应，并列出问题与改法
- **地址**：分别显示 IPv4 与 IPv6 出口，标注原生 / 6to4 / Teredo、ASN 与国家，点击复制；可一键隐藏
- **IPv4 与 IPv6 对比**：Cloudflare、Google、Akamai、DNSPod 各有一个只走 IPv4 和一个只走 IPv6 的入口，同时测已建好连接的往返，差值中位数在 10ms（或 15%）内算一样快
- **分享**：`#v6=` 链接只含每项耗时与地址类型，不含 IP；也可导出 1200×630 PNG

浏览器看不到路径 MTU 与 Happy Eyeballs 的实际等待时间，这两项需要服务端配合，纯前端版本不做。

## 出口对照

`/egress` 页同时问 51 个来源「我是谁」，一个来源就是一次普通请求，看的是它眼里的你。

- **六个组**：国内站点（5）、国际站点（10）、AI 服务（12）、常用网站（12）、双栈与骨干（8）、UDP / STUN（6），每组读到的地址、耗时与失败原因都单列
- **合并出口**：同一 ASN 的地址算一个出口，字母 A、B、C 标出先后；机房与云主机名（AWS、DigitalOcean、Hetzner、Cloudflare 等）判为代理，本机出口标 D，代理出口标 P
- **七项结论**：路线是否一致、有没有例外（某类站点走了另一条路）、AI 服务是否可达、WebRTC 是否漏出另一个地址、NAT 类型、IPv6 是否可用、时区是否与出口对得上
- **分享**：`#eg=` 链接只含每个探测器的成败、耗时与出口的国家 / 网络，不含 IP

## IP 质量

`/ip-quality` 页把 12 个来源的读数交叉比对，给一个 100 分制的评分。可以查自己的出口，也可以填任意地址。

- **来源**：Cloudflare、ipwho.is、ip-api、ip.sb、ipapi.is、ipquery、ipapi.co、RDAP、Shodan InternetDB、ip.guide 等，每家读到什么都单独列出，读不到就标红
- **类型判断**：住宅 / 机房 / 移动网络、是否代理 / VPN / Tor、有没有滥用记录，各家说法不一致时并列展示
- **邮件黑名单**：8 个常用 DNSBL 通过 DoH（`dns.alidns.com`）查询，只有 A 记录落在 `127.0.0.0/8` 且不是 `127.255.255.x` 才算被列进去；IPv6 地址不参与这项查询
- **评分**：满分 100，机房 −20、代理 −20、VPN −15、Tor −40、有滥用记录 −10、欺诈分按 0.35 折算，每命中一个黑名单 −6（最多扣 24）；等级 A ~ F
- **分享**：`#iq=` 链接保存地址与逐项结论，不含其他信息

## 解锁检测

`/unlock` 页逐个问服务「你看到我在哪」，把结果汇成成绩单。

- **148 个服务**：AI、影音、社交、地区服务四类，都可点进官网
- **三种问法**：Cloudflare 的 trace 读它看到的国家；服务自己的公开接口读地区、是否有片源（NBC 需要 POST、DAZN 需要先登录态）；读不出就用纯连通性推测，并明确标成「推测」
- **成绩单**：AI / 影音 / 社交各自算可用数，给 S ~ D 等级；再给总评与逐条分流建议（哪个服务在哪个国家不可用，支持列表里哪条线路可以）
- **各服务看到的地区**：不同服务看到不同国家，说明规则是按域名分流的
- **分享**：`#un=` 链接只含每个服务的结论与地区，不含 IP

## 隐私画像

`/privacy` 页把「网站不用询问就能读到什么」摊开：87 项，分网络、各站点看到的出口、请求头、语言与时区、设备、浏览器环境、指纹七组。

- **画像**：把读数拼成一句话——出口在哪、哪家运营商、DNS 在哪、什么设备什么浏览器、屏幕与显卡、语言时区，以及网站会因此给你贴上的标签
- **伪装检测 11 项**：系统时区对出口时区、浏览器语言对出口国家、系统里装的语言包、DNS 是否泄露、有没有分流、WebRTC 有没有漏地址、出口是不是机房、UA 与客户端提示是否自洽、浏览器接口有没有被改写过、指纹是否稳定、是不是自动化工具；红扣 16 分、黄扣 7 分，给出 A+ ~ F
- **一键隐藏地址**：地址、城市、坐标、DNS、反向解析、WebRTC 与各出口同时打码，方便截图
- **分享**：`#pv=` 链接只含每项结论、画像摘要与指纹编号，不含 IP、DNS 和坐标

指纹部分是本机算的：画布、WebGL 参数、音频、数学函数、字体宽度与文字度量各自取 SHA-256，再与系统、屏幕、核数、显卡拼成硬件编号。

## Bufferbloat 评级

测速不是只看峰值。路由器缓冲区排满时，延迟会被排队顶起来，视频会议卡顿、游戏跳 ping 大多来自这里。

实现上分两步：点开始后先在**无负载**状态打 4 次小请求取中位数作为基线（第一发是冷启动，丢掉了），然后在下载压满带宽的同时每 500ms 探测一次，取满载中位数。两者相减就是「多出来的排队延迟」。

| 增量 | 评级 | 含义 |
| --- | --- | --- |
| ≤ 5ms | A+ | 几乎无感 |
| 5–30ms | A | 轻微 |
| 30–60ms | B | 可感知 |
| 60–200ms | C | 明显卡顿 |
| 200–400ms | D | 严重 |
| > 400ms | F | 基本不可用 |

阈值与 Waveform 一致。评级会随下载结果一起写进历史记录与 CSV。

## 成绩卡

主页「成绩卡」按钮把最近一次测速画成 1200×630 的分享图（2x 输出），支持下载 PNG 与复制到剪贴板。

- 全部在 canvas 本地绘制，不含 IP、不含任何身份信息
- 最近一次结果存在 `localStorage`，刷新页面后仍可导出

## 离线与安装

构建时 `vite.config.ts` 里的 `precacheManifest()` 插件会输出 `dist/precache.json`，列出全部 js/css 产物；`public/sw.js` 在安装阶段按清单预热，因此**首次访问后断网也能打开**（含 `/diagnostics`）。

- 导航请求走 network-first，断网回落到缓存的 `index.html`
- 静态资源 cache-first，只缓存同源请求，第三方接口一律不碰
- 静态服务器普遍返回 `Vary: Origin`，缓存匹配统一用 `ignoreVary`
- Service Worker 只在生产构建注册，开发时不会干扰热更新

浏览器地址栏出现「安装」图标即可装成桌面应用；iOS 用 Safari 分享 → 添加到主屏幕（图标为 `apple-touch-icon.png`）。

## 关于「无后端」

- 没有账号体系、没有上报、没有排行榜，测速数据不离开浏览器。
- 出口 IP 与归属地走第三方公开接口（`ipwho.is`，失败时回退 `ipapi.co`），只发送一次普通请求；接口不可用时相关卡片显示为占位，不影响测速。
- 延迟探测使用公共 204 端点（华为 / Cloudflare）。
- 全球延迟页会直接向被测服务、公开 IP 接口与 STUN 服务器发请求，均为浏览器直连，不经过本项目；结果链接与分享图不含 IP。
- IPv6 测试会访问 Cloudflare、Google、DNSPod、阿里 DNS、ipify、icanhazip 等公开端点，只读它们的应答；分享链接与分享图不含 IP。
- 出口对照、IP 质量、隐私画像会访问 Cloudflare 的 `cdn-cgi/trace`、ipwho.is、ip.sb、ip.ipip.net、DoH 与 STUN，均为浏览器直连，结果链接不含 IP
- 解锁检测会向各服务自己的公开接口发请求，打不开的服务如实显示「打不开」，不代表该服务本身的状态
- 网络拓扑会向小米 / 腾讯 / 哔哩哔哩的 STUN 服务器发绑定请求以获取 NAT 映射，不建立数据通道、不传输内容；Chrome 会把内网地址混淆成 `.local`，此时卡片显示「已被浏览器隐藏」。
- 构建产物是纯静态文件，可直接丢到任意静态托管或本地打开。
